- **WebSocket Servers (`WSServer`, `SecureWSServer`)**: Implemented wrappers using composition.

## 3. Current Problems & Blockers

**Sandbox Test Failure (`quasar_net_sandbox`)**
The `TestSandbox.cpp` integration test for WebSockets is currently failing/crashing. 
*   **Symptom 1**: Lua script errors reporting `attempt to call a nil value (method 'onWSConnected')`. This implies the Lua callbacks are either not being registered correctly on the C++ side, or the C++ `InternalServer`/`InternalClient` overrides are not firing.
*   **Symptom 2**: Complex inheritance hierarchies in `CppServer` (e.g., `WSServer` inheriting from `HTTPServer` and `TCPServer`) caused signature mismatches when trying to override connection callbacks (`onConnected` vs `onWSConnected`). 
*   **Current State**: The wrappers have been migrated to Composition (`m_client = std::make_shared<InternalClient>(...)`), but the exact wiring of `WSSession` events back to the Lua proxy needs precise debugging.
