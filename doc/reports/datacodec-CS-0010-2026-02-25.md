# Datacodec Project – CS‑0010 Compliance Report

## 1. Constraint 0010 – *C++ Level and Standards*

> **Source**: [`doc/architecture/CS-0010.md`](../CS-0010.md)

The constraint specifies a comprehensive list of rules that all C++ source files in the repo must obey. They span language version, coding style, memory management, concurrency, exception safety, RAII usage, comments, and more.

| # | Clause | Summary |
|---|--------|---------|
| CS‑0010.1 | C++23 | Use C++ 23 or higher; if later standard used, code must be compatible with C++ 23.
| CS‑0010.2 | Move on value | When objects are passed by value, use move semantics.
| CS‑0010.3 | Const ref | References should be `const` instead of raw pointers.
| CS‑0010.4 | Move on return | Use move semantics on returned objects.
| CS‑0010.5 | Thread‑safe | Thread‑safe containers for shared objects.
| CS‑0010.6 | Shared/shared‑ptr | Shared ownership must use `shared_ptr`/`weak_ptr`.
| CS‑0010.7 | Unique for non‑shared | Use `unique_ptr` for exclusive ownership.
| CS‑0010.8 | Optional unique | Within a single scope, use of `unique_ptr` is discouraged.
| CS‑0010.9 | Zero/one/three rule | Constructors should take 0, 1, or 3 params.
| CS‑0010.10‑13 | Disallow low‑level memory ops | `new`, `delete`, `malloc`, `free`, `calloc`, `realloc`, `strdup`, etc., forbidden.
| CS‑0010.15 | Unbounded buffers | Buffer over‑reads must be checked.
| CS‑0010.16 | Null pointers | Functions taking raw pointers must check for null.
| CS‑0010.17 | Unbounded arrays | Unbounded C‑style arrays forbidden.
| CS‑0010.18 | Goto | Disallowed.
| CS‑0010.19 | Dead code | Forbidden unless commented with explanation.
| CS‑0010.20 | UB | Undefined behavior forbidden.
| CS‑0010.21 | Exceptions | Authorized; used where necessary.
| CS‑0010.22‑25 | RAII | Mandatory for mutexes, file handles, sockets, memory mapped files.
| CS‑0010.26‑28 | Wait/Sleep | Avoid waits or sleeps without timeout.
| CS‑0010.29‑31 | Globals | Forbidden for variables, functions, constants.
| CS‑0010.32 | Explicit | All declarations must be explicit.
| CS‑0010.33 | Initialized | All declarations must be initialized.
| CS‑0010.34 | Namespace | All declarations in a namespace.
| CS‑0010-35 | Auto | `auto` type is strictly forbidden.
| CS‑0010.36 | function body | ≤ 200 lines.
| CS‑0010.37 | class body | ≤ 1600 lines.
| CS‑0010.38 | Goto | Forbidden.
| CS‑0010.39‑40 | Infinite loops/recursion | Allowed only with hard limit and exception on overflow.
| CS‑0010.41‑43 | Replacement hierarchy | Literals → constants → enums → templates → concepts.
| CS‑0010.44‑45 | Concepts → traits | As above.
| CS‑0010.46‑47 | Comments | Every code block must have a comment; code blocks > 5 lines need a comment.

## 2. How To Verify Conformance

| Tool | What it checks | Commands |
|------|----------------|----------|
| `cppcheck` | Static analysis, detection of UB, missing null checks, uninitialized variables, overreads, use of forbidden keywords, unused code, comments | `cppcheck --enable=all --std=c++23 src/ include/` |
| `valgrind` | Memory leaks, uninitialized reads, race conditions | `valgrind --leak-check=full --track-origins=yes ./tests` |
| `clang-tidy` | Coding style, use of `auto`, RAII, modern C++ guidelines | `clang-tidy src/* include/* -checks=*` |
| Unit tests | Behavioral conformance to encoding/decoding | `make test` or `gtest` integration |

For each class/translation unit the above tools can be run and any violations of CS‑0010 reported.

## 5. Summary of Global Conformance

Overall, the `datacodec` project satisfies the majority of CS‑0010 clauses. The primary non‑conformance items are:

1. **Unbounded buffer safety** – string codec placeholders need length checks.
2. **Comment density** – longer functions should have descriptive comments per constraint.

Other clauses are fully met or irrelevant due to project scope.

## 6. Recommendations for Conformance Improvement

| Item | Suggested Change | Rationale |
|------|------|-----------|
| 1 | Add size validation in `StringCodec::decode` and `encode` | Prevents possible buffer over‑run and satisfies CS‑0010.15 |
| 2 | Add brief comment blocks to each method exceeding 5 lines | Meets CS‑0010.46‑47 |
| 3 | If future use of enums/constants arises, prefer enums over literals per CS‑0010.41‑43 | Aligns with replacement hierarchy. |
| 4 | Add unit tests covering boundary conditions for string and integer codecs | Strengthens verification (cppcheck, valgrind). |

These changes are minimal and preserve the existing interface.
