# Goal

Implement Passive Master capabilities in `resoem`, enabling High Availability (Master Redundancy) and Non-Intrusive Bus Monitoring.

# Details

## Context
Industrial systems requiring 24/7 uptime cannot afford a single point of failure at the master level. By implementing a "Passive" mode, `resoem` can either act as a redundant standby that takes over on failure or as a diagnostic "Spy" that monitors traffic without hardware intervention.

## Requirements

### 1. Passive Monitor Mode ("Spy Mode")
- [ ] [TSK-20260410-005.1] **Listen-Only Socket**: Implement a raw socket mode that disables all TX (Transmit) operations at the driver level.
- [ ] [TSK-20260410-005.2] **Live Process Image Reconstruction**: Develop logic to reconstruct the `NamedObject` tree's values by sniffing the data fields of passing EtherCAT datagrams.
- [ ] [TSK-20260410-005.3] **Mailbox Transaction Shadowing**: Implement stateful tracking of asynchronous mailbox traffic.
    - **CoE/SDO**: Observe request/response pairs from the primary master to update internal `NamedObject` mirrors.
    - **FoE**: Strictly ignore File over EtherCAT transfers to minimize overhead.
- [ ] [TSK-20260410-005.4] **WKC Tracking**: Monitor the Working Counter of passing frames to detect slave failures from a passive perspective.

### 2. Standby Master (Redundancy)
- [ ] [TSK-20260410-005.5] **Redundancy Ring Topology**: Support physical connection via a redundancy ring (secondary master connected to the OUT port of the last slave).
- [ ] [TSK-20260410-005.6] **Dedicated Redundant Master**: Implement a specialized master class (`RedundantEthercatMaster`) optimized for ring-based passive sniffing and active takeover.
- [ ] [TSK-20260410-005.7] **Master Health Monitoring**: Implement a heartbeat detection mechanism that listens for the primary master's frames on the physical interface.
- [ ] [TSK-20260410-005.8] **Process Image Synchronization**: Ensure the standby master's internal process image is kept in sync with the active bus traffic circulating through the ring.
- [ ] [TSK-20260410-005.9] **Bumpless Takeover**: Implement the logic to enable TX and take control of the bus cycle.
    - **Trigger**: Strictly based on a configurable timeout detecting a complete loss of frames from the primary master (Phase 1).
    - **Timing**: Target takeover completion within < 2 bus cycles of detection.
    - **State Recovery**: Upon takeover, attempt to transition all slaves to **SAFE-OP** or **OP**. Implement resilience for unresponsive slaves or degraded situations to ensure the bus remains operational.
- [ ] [TSK-20260410-005.10] **Master ID Arbitration**: Support a simple arbitration protocol (via alias or IP) to decide which master starts as Active vs. Standby.

### 3. Redundancy Communication Link
- [ ] [TSK-20260410-005.11] **Inter-Master Sync**: Implement an optional secondary Ethernet or ZeroMQ link between two `resoem` instances to synchronize internal EtherCAT state machines and high-level application states.
    - **Note**: Precision clock synchronization (PTP/DC) is assumed to be managed by the host operating system and is out of scope for this master implementation.

# Implementation Plan

1. **Driver Enhancement**: Add a `setPassive(bool)` flag to `RawSocket` to suppress `send()` calls.
2. **Sniffer Logic**: Enhance `ProcessImage` to update itself based on received frames even if they weren't sent by the local instance.
3. **Takeover Controller**: Implement a state machine in `EthercatMasterService` to manage the transition from Standby to Active.
4. **Validation**: Use a TAP (Terminal Access Point) to simulate bus traffic and verify the passive master's reconstruction accuracy.

# Test and validation

- **Synchronization Fidelity**: Compare the `NamedObject` tree of an Active master and a Passive master; verify they match with zero lag.
- **Failover Timing**: Measure the time between "Primary Stop" and "Secondary Start"; target < 10ms for standard industrial apps.
- **Network Load**: Verify that Passive mode adds zero extra traffic to the EtherCAT bus.
