# Goal

Implement OPC UA (Open Platform Communications Unified Architecture) server and client capabilities within the Quasar framework, enabling seamless industrial interoperability and secure data exchange between the `quasar::named` object hierarchy and external industrial automation systems.

# Details

## Context

OPC UA is the industry standard for secure, reliable, and vendor-neutral data exchange. To position Quasar as a robust framework for industrial infrastructure and "Industry 4.0" applications, it must be able to expose its internal state (represented by `NamedObject` trees) as an OPC UA Address Space and interact with external sensors, PLCs, and SCADA systems as an OPC UA client.

## Requirements

- [ ] [TSK-20260311-005.1] **OPC UA Stack Integration**:
    - [ ] [TSK-20260311-005.1.1] Select and integrate a high-performance C/C++ OPC UA stack (e.g., `open62541` or a similar industrial-grade library).
    - [ ] [TSK-20260311-005.1.2] Configure CMake to manage the dependency (via `FetchContent` or system package).
- [ ] [TSK-20260311-005.2] **Address Space Mapping (Server)**:
    - [ ] [TSK-20260311-005.2.1] Implement a mechanism to automatically map a `NamedObject` hierarchy to an OPC UA Address Space.
    - [ ] [TSK-20260311-005.2.2] Map Quasar `coretypes` (Integer, FloatingPoint, Boolean, String, Buffer) to corresponding OPC UA built-in types.
    - [ ] [TSK-20260311-005.2.3] Support real-time synchronization between `NamedObject` field updates and OPC UA Variable Nodes.
- [ ] [TSK-20260311-005.3] **Method Mapping**:
    - [ ] [TSK-20260311-005.3.1] Map `ActiveEntity` reflexive methods to OPC UA Method Nodes, allowing external clients to invoke Quasar functions.
- [ ] [TSK-20260311-005.4] **OPC UA Client Capabilities**:
    - [ ] [TSK-20260311-005.4.1] Implement an asynchronous client capable of browsing, reading, and writing to remote OPC UA servers.
    - [ ] [TSK-20260311-005.4.2] Support Monitored Items and Subscriptions to receive push notifications for data changes.
- [ ] [TSK-20260311-005.5] **Security and Authentication**:
    - [ ] [TSK-20260311-005.5.1] Support standard OPC UA security profiles (None, Sign, SignAndEncrypt).
    - [ ] [TSK-20260311-005.5.2] Implement X.509 certificate management and user-based authentication (Username/Password).
- [ ] [TSK-20260311-005.6] **Scripting Bridge**:
    - [ ] [TSK-20260311-005.6.1] Expose both server and client capabilities to the Lua/Python scripting environments as optional plugins.

## Implementation Plan

1. **Stack Selection & Scaffolding**: Evaluate `open62541` performance and license compatibility. Create a new module `cmake-projects/opcua`.
2. **Type Mapping Layer**: Develop a robust conversion layer between `quasar::coretypes::Variant` and `UA_Variant`.
3. **Server Implementation**:
    - Create `OpcUaServer` class.
    - Implement a tree-walking visitor to populate the address space from a `NamedObject` root.
    - Hook into `NamedObject` change notifications (via `IObserver` pattern) to push updates.
4. **Client Implementation**:
    - Create `OpcUaClient` class with a thread-safe asynchronous API.
    - Implement a subscription manager to handle incoming data change notifications.
5. **Security Layer**: Add utilities for generating/loading application instance certificates.
6. **Scripting Bindings**: Map the high-level API to Lua using `sol2`.

# Test and validation

- **Compliance Testing**: Validate the server using the OPC Foundation's Compliance Test Tool (CTT) or equivalent open-source alternatives (e.g., `freeopcua` tools).
- **Interoperability**: Verify connectivity and data exchange with standard OPC UA clients (e.g., UA Expert) and servers (e.g., Ignition, Kepware).
- **Stress Test**: Benchmark address space population and update rates for 10,000+ nodes.
- **Security Audit**: Verify that encrypted connections correctly reject invalid certificates and enforce configured security policies.
- **Round-trip Validation**: Create a test where a Quasar client connects to a Quasar server and verifies identical data across the network.

## Expected result

A high-performance, industrial-grade OPC UA integration that allows Quasar to serve as both an edge gateway and a central monitoring hub.
