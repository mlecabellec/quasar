# Goal

Implement OPC UA (Open Platform Communications Unified Architecture) server and client capabilities within the Quasar framework, enabling seamless industrial interoperability and secure data exchange between the `quasar::named` object hierarchy and external industrial automation systems. Both server and client shall be exposed as `NamedService`.

# Details

## Context

OPC UA is the industry standard for secure, reliable, and vendor-neutral data exchange. To position Quasar as a robust framework for industrial infrastructure and "Industry 4.0" applications, it must be able to expose its internal state (represented by `NamedObject` trees) as an OPC UA Address Space and interact with external sensors, PLCs, and SCADA systems as an OPC UA client.

- [ ] [TSK-20260311-005.5] **Scripting Bridge**:
    - [ ] [TSK-20260311-005.5.1] Expose both server and client services to the Lua/Python scripting environments.

# Test and validation

- **Transport Verification**: Test connectivity over TCP, UDP unicast, and UDP multicast for both client and server.
- **Dynamic Mapping**: Verify that adding/removing `NamedObject` children at runtime correctly updates the OPC UA address space.
- **Method Execution**: Call a `NamedMethod` via an OPC UA client and verify the execution in Quasar.
- **Data Synchronization**: Verify that changes in a remote server are correctly reflected in the client's `NamedObject` tree.
- **Compliance**: Validate using standard OPC UA testing tools.

## Expected result

A flexible OPC UA integration where servers and clients are first-class citizens in the `NamedObject` hierarchy, supporting modern industrial networking protocols including UDP multicast.
