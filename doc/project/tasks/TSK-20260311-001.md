# Goal

Implement a set of advanced tree transformation and manipulation capabilities for the `quasar::named` library, allowing for efficient, functional-style structural and content modifications of `NamedObject` hierarchies.

# Details

## Context

The current `quasar::named` implementation provides basic traversal, searching, and deep copying. However, as the system grows, there is a need for more expressive and declarative ways to transform entire trees or subtrees. This includes mapping trees to new structures, filtering nodes while preserving hierarchy, and aggregating data across the tree. These capabilities are essential for tasks like converting between different modeling domains, pruning inactive branches, or extracting specific views of the system state.

## Requirements

- [ ] [TSK-20260311-001.1] **Functional Tree Map**: Implement a `map` utility that creates a new tree by applying a transformation function to each node of an existing tree.
    - [ ] [TSK-20260311-001.1.1] The transformation function shall take a `std::shared_ptr<NamedObject>` and return a new `std::shared_ptr<NamedObject>`.
    - [ ] [TSK-20260311-001.1.2] The resulting tree shall maintain the same topology as the original, but with the transformed nodes.
- [ ] [TSK-20260311-001.2] **Tree Filtering**: Implement a `filter` utility that returns a new tree containing only nodes that satisfy a given predicate.
    - [ ] [TSK-20260311-001.2.1] If a node matches the predicate, all its ancestors must be included in the new tree to maintain connectivity, even if they don't match the predicate.
    - [ ] [TSK-20260311-001.2.2] Children of matching nodes shall be recursively filtered.
- [ ] [TSK-20260311-001.3] **Tree Folding (Reduce)**: Implement a `reduce` (or `fold`) utility that aggregates data across the tree.
    - [ ] [TSK-20260311-001.3.1] Support both pre-order and post-order accumulation.
- [ ] [TSK-20260311-001.4] **In-place Pruning**: Implement a `prune` utility that modifies an existing tree by removing subtrees based on a predicate.
    - [ ] [TSK-20260311-001.4.1] The operation shall be thread-safe following the project's locking patterns.
- [ ] [TSK-20260311-001.5] **Subtree Grafting**: Implement a `graft` utility to safely move a subtree from one location (potentially in a different tree) to a new parent.
    - [ ] [TSK-20260311-001.5.1] Ensure name uniqueness in the target parent.
    - [ ] [TSK-20260311-001.5.2] Update all internal parent/child references correctly.
- [ ] [TSK-20260311-001.6] **Path-based Merging**: Implement a `merge` utility to combine two trees based on their hierarchical paths.
    - [ ] [TSK-20260311-001.6.1] Provide configurable conflict resolution strategies (e.g., replace, ignore, rename).

## Implementation Plan

1. **Design Transformation API**: Define the generic interfaces for transformers and predicates in `Traversal.hpp`.
2. **Implement Map/Filter**: Develop the recursive algorithms for `map` and `filter` in `Traversal.cpp`. Ensure they handle different derived types of `NamedObject` correctly (possibly using `clone()` and `getType()`).
3. **Implement Reduce**: Add the accumulation logic, supporting both top-down and bottom-up aggregation.
4. **Implement Pruning and Grafting**: Add structural manipulation methods, ensuring they respect the `NamedObject` thread-safety and internal consistency rules.
5. **Implement Merging**: Develop the path-aware merging logic.
6. **Documentation**: Update Doxygen comments in `Traversal.hpp` to describe the new utilities.

# Test and validation

- **Topology Integrity**: Verify that `map` with an identity transformation produces a tree with identical structure.
- **Filtering Correctness**: Test that `filter` correctly preserves ancestor paths for matching leaf nodes.
- **Aggregation Accuracy**: Validate `reduce` with arithmetic operations (e.g., summing `NamedInteger` values) and string concatenation.
- **Pruning Safety**: Ensure `prune` correctly releases memory for the removed subtrees and doesn't leave dangling references.
- **Grafting Robustness**: Test moving subtrees between different tree roots and verify all references (parent, children, siblings) are updated.
- **Conflict Handling**: Verify `merge` correctly applies resolution strategies during name collisions.
- **Performance**: Validate that transformations on large trees (10,000+ nodes) complete within reasonable time and don't exceed the recursion/loop hard limits.

## Expected result

A comprehensive set of tree transformation utilities in the `quasar::named::traversal` namespace, enabling powerful and safe manipulations of the `NamedObject` hierarchy.
