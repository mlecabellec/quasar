# Goal

Implement a highly expressive, configurable, and high-performance XSLT-inspired tree transformation and reinterpretation engine for the `quasar::named` library. This engine must handle non-isomorphic hierarchical transformations, support both independent and shared memory life-cycles, provide declarative rule-based bindings, and allow zero-copy deep reinterpretation of raw binary data (`NamedBuffer`/`NamedBitBuffer`) into hierarchical primitive views.

# Details

## Context

As the Quasar project integrates complex industrial protocols (like EtherCAT) and dynamically maps network byte streams into high-level C++ model hierarchies, pure structural copying or manual parsing becomes a major performance bottleneck and conceptual burden. The system requires an advanced transformation layer that natively supports XSLT-style declarative rule matching to morph trees. Furthermore, it must support "in-place" transformation, and allow for multiple disparate logical views ("Slicing Trees") to exist over the exact same underlying memory buffers without duplication (Zero-Copy). 

## Detailed Requirements

### 1. Declarative Rule-Based Transformation (XSLT-Inspired)
- [ ] [TSK-20260311-001.1] **Transformation Engine API**: Implement a `TreeTransformer` class that accepts a source `NamedObject` tree and evaluates it against a registered set of `TransformationRule`s.
    - [ ] [TSK-20260311-001.1.1] **Rules and Matchers**: A `TransformationRule` consists of a `Predicate` (analogous to XSLT `match="..."`) and a `Generator` (analogous to an XSLT template body).
    - [ ] [TSK-20260311-001.1.2] **Topology Morphing**: The `Generator` can return zero, one, or multiple `NamedObject` instances. It can unconditionally drop nodes, flatten subtrees, or artificially inject deep nested hierarchies that did not exist in the source.
    - [ ] [TSK-20260311-001.1.3] **Transformation Context**: Provide a `TransformContext` object to the `Generator` during evaluation. This context must expose the current node, its parent path, its siblings, its depth, and a mechanism to recursively trigger transformations on children (analogous to `<xsl:apply-templates/>`).

### 2. Transformation Execution Modes
- [ ] [TSK-20260311-001.2] **Out-of-Place (Functional) Mode**: `TreeTransformer::transform(src)` evaluates the rules and produces a completely new root `NamedObject` containing the generated tree topology.
- [ ] [TSK-20260311-001.3] **In-Place (Mutating) Mode**: `TreeTransformer::transform_in_place(root)` evaluates the rules and directly mutates the physical `std::list<std::shared_ptr<NamedObject>>` children links of the existing tree, respecting `recursive_mutex` thread-safety constraints.

### 3. Memory & Ownership Policies (The "Copy vs Share" Matrix)
- [ ] [TSK-20260311-001.4] **Memory Policy Configuration**: Transformation generation must respect a strictly defined memory policy when moving data from the source tree to the target tree.
    - [ ] [TSK-20260311-001.4.1] **POLICY_DUPLICATE**: The generated tree is fully physically independent. Leaf nodes containing data (e.g., `NamedBuffer`, `NamedInteger`) undergo deep copies of their underlying payload.
    - [ ] [TSK-20260311-001.4.2] **POLICY_SHARE**: The generated tree represents a new structural topology, but the leaf nodes maintain shared ownership (via `std::shared_ptr` aliasing or slice references) of the original tree's buffer payloads. Modifying data in the new tree modifies the old tree's data.

### 4. Advanced Slicing and Multi-View Trees
- [ ] [TSK-20260311-001.5] **Multi-Slicing Hierarchies**: A single `NamedBuffer` or `NamedBitBuffer` must be capable of acting as the root of multiple independent "Slicing Trees".
    - [ ] [TSK-20260311-001.5.1] The transformation engine must allow applying different slice-generator rules to the same source buffer, resulting in distinct hierarchical views over the same physical memory chunk.
    - [ ] [TSK-20260311-001.5.2] **Safety Bounds**: The system must mathematically guarantee that no generated slice or sub-slice exceeds the memory bounds of the root buffer.

### 5. Hierarchical Buffer Reinterpretation ("Pseudo-Primitives")
- [ ] [TSK-20260311-001.6] **Buffer-to-Primitive Binding**: Support the reinterpretation of contiguous memory ranges within a `NamedBuffer` or `NamedBufferSlice` directly into specialized `NamedObject` primitives (e.g., `NamedInteger`, `NamedFloatingPoint`, `NamedBoolean`, `NamedArray`).
    - [ ] [TSK-20260311-001.6.1] **Pseudo-Primitive Leaves**: These primitives can be attached as hierarchical child nodes *underneath* the buffer/slice node.
    - [ ] [TSK-20260311-001.6.2] **Zero-Copy Reinterpretation**: These child primitive nodes do not own their memory. Calling `set()` or `get()` on the `NamedInteger` directly reads/writes to the calculated `offset + length` within the parent buffer's memory span. Any structural transformation utilizing `POLICY_SHARE` inherently utilizes these pseudo-primitives.
- [ ] [TSK-20260311-001.7] **Explicit Cast Transformations**: Provide predefined transformation rules (e.g., `rule::CastBufferToStructure<T>`) that automatically consume a buffer and expand it into a tree of pseudo-primitives based on a defined offset map or schema.

## Implementation Plan

1. **Memory & Slicing Core Expansion**: Update the core `quasar::named` classes to support the `CopyPolicy` enum. Architect the "Pseudo-Primitive" pattern by creating generalized `BoundValue` mixins that `NamedInteger`/`NamedFloatingPoint` can inherit to act as views over a parent's pointer array.
2. **Transformer & Context Design**: Create `TreeTransformer`, `TransformationRule`, and `TransformContext` interfaces in `Traversal.hpp`. Implement recursive traversal dispatch logic (the XSLT `apply-templates` equivalent).
3. **Execution Engines**: Implement the two distinct execution engines (`transform` for topology creation, `transform_in_place` for topology mutation), ensuring the `recursive_mutex`es are locked correctly to prevent cycle generation or race conditions during mutation.
4. **Reinterpretation Handlers**: Write the specialized predefined rules (e.g., `SliceGenerator`, `PrimitiveBinder`) to map byte offsets to child object instantiations.

# Test and validation

- **Rule Evaluation Logic**: Create a test where rules filter specific names, rename nodes dynamically based on depth, and output 3 objects for every 1 object matched. Validate the resulting topology.
- **In-Place Mutation Safety**: Run a highly concurrent fuzz test where 4 threads are performing `transform_in_place` pruning/renaming on overlapping sections of a 5,000 node tree, verifying no deadlocks occur and the tree structure remains valid.
- **Strict Memory Independence**: Under `POLICY_DUPLICATE`, transform a buffer tree, mutate the new buffers, and `ASSERT_NE` against the original buffer payloads.
- **Shared Memory Concurrence**: Under `POLICY_SHARE`, map overlapping `NamedBufferSlice` trees. Write an integer block to Tree A, and mathematically verify the bitwise changes appear instantly at the correct offsets in Tree B's slices.
- **Pseudo-Primitive Bounds Checking**: Attempt to create a rule that binds a `NamedInteger` (4 bytes) at offset `N-2` of a buffer of size `N`. Validate that an out-of-bounds structure exception is strictly thrown during transformation.

## Expected result

A highly sophisticated, XSLT-inspired parsing and transformation engine capable of safely mapping industrial protocol datagrams into strongly typed OOP hierarchies at near-zero-copy memory overhead.
