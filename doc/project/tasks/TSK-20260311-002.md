# Goal

Implement a networking plugin for the Quasar scripting environment, enabling the creation of high-performance TCP, UDP, HTTP, HTTPS, and WebSocket servers directly from Lua scripts.

# Details

## Context

To extend Quasar's capabilities for distributed systems, remote monitoring, and web-based control interfaces, the scripting environment requires a robust networking stack. By leveraging the existing `CppServer` and `asio` libraries, this task aims to provide a modular, asynchronous networking API for hosting services in Lua. This fulfills the need for rapid prototyping and deployment of server-side components without core engine recompilation.

## Implementation Plan

1. **Architecture Design**: Define a C++ "Trampoline" system to bridge asynchronous `CppServer` events to Lua callbacks safely.
2. **Server Bindings**: Implement the core TCP/UDP server wrappers and expose them via `sol2`.
3. **Web Stack Integration**: Implement HTTP/WebSocket handlers that route requests to Lua.
4. **SSL/TLS Utilities**: Build configuration helpers for server-side OpenSSL parameters.
5. **CMake Configuration**: Add the plugin as a new shared library target in `cmake-projects/scripting/plugins/net`.

# Test and validation

- **Service Hosting**: Verify that Lua-hosted servers (TCP, UDP, HTTP, WS) correctly accept connections and process data from external clients (e.g., `curl`, `telnet`).
- **Multicast Validation**: Test that UDP multicast servers correctly broadcast data to multiple network listeners.
- **Security Validation**: Verify that HTTPS/WSS servers correctly present certificates and handle encrypted traffic.
- **Memory Safety**: Use ASan to ensure no leaks occur when many sessions are created and destroyed.

## Expected result

A high-performance networking server plugin for the Quasar scripting environment.
