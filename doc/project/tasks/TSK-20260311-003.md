# Goal

Implement networking client capabilities for the Quasar scripting environment, enabling Lua scripts to connect to and interact with external TCP, UDP, HTTP, HTTPS, and WebSocket services.

# Details

## Context

To enable Quasar scripts to act as active participants in distributed systems—such as fetching configuration from remote APIs, sending telemetry to central collectors, or interacting with existing industrial protocols—the scripting environment requires a robust networking client stack. This task leverages `CppServer` and `asio` to provide asynchronous, high-performance client bindings to the Lua environment.

## Requirements

- [ ] [TSK-20260311-003.1] **TCP Client Support**:
    - [ ] [TSK-20260311-003.1.1] Expose `TCPClient` to Lua with support for asynchronous connections.
    - [ ] [TSK-20260311-003.1.2] Map C++ client callbacks (`onConnected`, `onDisconnected`, `onReceived`, `onError`) to Lua functions.
    - [ ] [TSK-20260311-003.1.3] Implement automatic reconnection logic configurable from Lua.
- [ ] [TSK-20260311-003.2] **UDP Client Support**:
    - [ ] [TSK-20260311-003.2.1] Expose `UDPClient` to Lua for datagram communication.
    - [ ] [TSK-20260311-003.2.2] Support joining and leaving multicast groups from the client side.
- [ ] [TSK-20260311-003.3] **Web Clients (HTTP/HTTPS)**:
    - [ ] [TSK-20260311-003.3.1] Expose `HTTPClient` and `HTTPSClient` (or a unified `HTTPClientEx`) to Lua.
    - [ ] [TSK-20260311-003.3.2] Support standard HTTP methods (GET, POST, PUT, DELETE, etc.) with asynchronous execution.
    - [ ] [TSK-20260311-003.3.3] Provide easy-to-use Lua wrappers for sending headers, query parameters, and request bodies.
- [ ] [TSK-20260311-003.4] **WebSocket Clients (WS/WSS)**:
    - [ ] [TSK-20260311-003.4.1] Implement WebSocket and Secure WebSocket client bindings.
    - [ ] [TSK-20260311-003.4.2] Support full-duplex communication with Lua callbacks for received frames.
- [ ] [TSK-20260311-003.5] **Client Security and SSL/TLS**:
    - [ ] [TSK-20260311-003.5.1] Expose `SSLContext` for client-side configuration (root CA paths, peer verification modes).
    - [ ] [TSK-20260311-003.5.2] Support certificate-based client authentication.
- [ ] [TSK-20260311-003.6] **Plugin Integration**:
    - [ ] [TSK-20260311-003.6.1] Integrate client components into the `quasar.net.client` Lua namespace within the same networking plugin.

## Implementation Plan

1. **Client Bridge Architecture**: Expand the "Trampoline" system to handle client-side asynchronous events (e.g., handshake completion, connection timeouts).
2. **Client Bindings**: Implement the Lua wrappers for `TCPClient`, `UDPClient`, and `HTTPClientEx`.
3. **Async Request/Response Mapping**: Map C++ futures or callback patterns to Lua-friendly asynchronous calls (possibly using Lua coroutines or simple callback registration).
4. **Security Configuration**: Implement Lua APIs for setting up trusted certificates and peer verification.
5. **Integration**: Ensure both server (TSK-20260311-002) and client components coexist seamlessly within the `quasar.net` plugin.

# Test and validation

- **External Connectivity**: Verify that Lua scripts can successfully perform GET/POST requests against public APIs (e.g., `httpbin.org`) and local test servers.
- **Protocol Fidelity**: Test TCP and WebSocket clients against standard echo servers to ensure no data corruption or framing issues.
- **Resilience**: Validate that clients handle connection failures, timeouts, and server restarts gracefully according to Lua-configured policies.
- **Security Validation**: Verify that HTTPS/WSS clients correctly validate server certificates against provided root CAs and fail on untrusted connections.

## Expected result

A high-performance networking client suite for the Quasar scripting environment.
