# Goal

Add support for mode industrial protocols.

# Details

## Context

The new component-based architecture must support integration with diverse external hardware, requiring robust and standard protocol support. Note that any architecture diagrams created should account for PlantUML constraints (v1.2020.02).

## Requirements


- [TSK-20260303-002.1] Define a unified `IProtocol` interface and a component-based plugin architecture to ensure interoperability and hot-swappability of industrial protocol drivers.
- [TSK-20260303-002.2] Implement a pluggable Modbus TCP driver component that maps industrial registers to `quasar::coretypes` and utilizes `quasar::named` for endpoint identification.
- [TSK-20260303-002.3] Develop an OPC UA client service integrated into the service-oriented architecture, ensuring UA nodes are translated to `quasar::coretypes` and cataloged via `quasar::named`.
- [TSK-20260303-002.4] Integrate an MQTT messaging service that leverages `quasar::named` for topic hierarchy management and `quasar::coretypes` for structured payload serialization.
- [TSK-20260303-002.5] Create a serial communication (RS-232/RS-485) driver module that abstracts physical layer specifics behind the common `IProtocol` interface.
- [TSK-20260303-002.6] Design an SNMP manager component for network infrastructure monitoring, mapping device OIDs to the `quasar::named` registry for consistent entity management.
- [TSK-20260303-002.7] Implement an LXI-compliant service driver to facilitate standardized Ethernet-based communication with instrumentation hardware within the component framework.
- [TSK-20260303-002.8] Implement an EtherCAT master service for high-performance fieldbus control, ensuring real-time synchronization of process data objects (PDO) with `quasar::coretypes` structures.






## Implementation Plan

1. Define the unified `IProtocol` interface and the component-based plugin architecture to enable hot-swappable driver modules [TSK-20260303-002.1].
2. Implement the Modbus TCP driver [TSK-20260303-002.2] and the Serial (RS-232/RS-485) abstraction [TSK-20260303-002.5], mapping internal registers to `quasar::coretypes`.
3. Develop the OPC UA client service [TSK-20260303-002.3] and the MQTT messaging service [TSK-20260303-002.4], leveraging `quasar::named` for endpoint and topic management.
4. Integrate the SNMP manager [TSK-20260303-002.6] for infrastructure monitoring and the LXI-compliant service [TSK-20260303-002.7] for instrumentation hardware.
5. Implement the EtherCAT master service to support high-performance real-time synchronization of process data objects [TSK-20260303-002.8].
6. Validate the entire protocol suite through integration tests, ensuring consistent serialization and entity identification across the `quasar` ecosystem.


# Test and validation

- Execute specific integration tests using software simulators (e.g., Modbus simulator, OPC UA test server).
- Validate the drivers natively on the target platforms: **Debian 12** and **Debian 13**.
- Introduce rigorous fault-tolerance testing (e.g., simulated link loss, connection recovery patterns, invalid frame handling).
- Run long-duration stability tests (48h+ runs without leaks).

## Expected result

A mature, fault-tolerant, hot-swappable set of industrial protocol drivers deployed and validated on target Debian architectures.
