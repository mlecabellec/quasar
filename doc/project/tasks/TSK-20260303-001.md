# Goal

Implement a modular, high-performance data logging and acquisition system within Quasar, allowing for real-time data capture, filtering, and persistent storage of system states and communication traffic.

# Details

## Context

To support high-fidelity system analysis and debugging, the framework requires a unified data acquisition infrastructure. Inspired by "Logies 3.0", the architecture must separate data sources (Devices), processing units (Filters), and storage backends (Recorders), providing a seamless flow from raw data to analytical outputs.

## Requirements

- [TSK-20260303-001.1] **Unified Logging Interface**: Define an abstract `ILogger` and `IRecorder` interface to decouple data sampling from storage formats.
- [TSK-20260303-001.2] **High-Performance CSV Recorder**: Implement a thread-safe CSV writer capable of logging $10,000+$ samples/sec with configurable precision and ISO-8601 timestamping.
- [TSK-20260303-001.3] **Binary & PCAP Storage**: Support industry-standard binary formats and PCAP encapsulation for network-level protocol logging, compatible with Wireshark.
- [TSK-20260303-001.4] **Pluggable Filter Pipeline**: Implement a filter chain architecture allowing real-time data transformations (Mathematical, Logical, and Bit-level) during the acquisition phase.
- [TSK-20260303-001.5] **Dynamic Sampling & Triggering**: Support on-demand and periodic sampling frequencies, with configurable trigger conditions (Edge, Value-threshold, System-event).
- [TSK-20260303-001.6] **Lua Scriptable Routing**: Integrate a Lua bridge to allow dynamic configuration of data routes and custom processing logic at runtime.
- [TSK-20260303-001.7] **Buffer Management**: Implement robust, non-blocking ring buffers or notification queues to prevent data loss during high-load bursts without stalling the main execution loops.

## Implementation Plan

1. **Foundational Interfaces**: Define `MemoryAccess`, `DataAccessor`, and `DataView` as the core abstractions for data visibility and subscription.
2. **Recorder Infrastructure**: Implement `ADevRecorder` base class and concrete `CsvFileWriter` and `PcapFileWriter` modules.
3. **Filter Engine**: Develop a suite of basic filters (Mathematical, Logical) and the `FilterTrigger` mechanism for conditional logging.
4. **Service Integration**: Establish the `LogiesService` as the central manager for all logging entities, integrated with the `quasar::named` registry.
5. **Scripting Bridge**: Map the core logging classes to the Lua environment via `LogiesApi`, enabling script-based control.
6. **Performance Benchmarking**: Validate throughput and latency under industrial-grade load scenarios.

# Test and validation

- **Throughput Stress Test**: Verify zero data loss at 50,000 samples/sec sustained for 1 hour.
- **Trigger Integrity**: Validate that trigger-based recorders start/stop within 1ms of the satisfying condition.
- **Memory Safety**: Run 24h stability tests under AddressSanitizer (ASan) to prove deterministic cleanup of dynamic pipelines.
- **Interoperability**: Verify that generated PCAP files are correctly parsed by latest stable Wireshark on **Debian 12**.
- **Lua Consistency**: Assert that 100% of the C++ API is accessible and functional from the Lua environment through exhaustive unit test scripts.

## Expected result

A robust, industrial-grade data logging framework that serves as the backbone for system monitoring, diagnostics, and data engineering.
