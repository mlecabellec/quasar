# Goal

Improve and expand the core type system in `quasar::named` and `quasar::coretypes` to support advanced modeling and scripting.

# Details

## Context

Structural improvements to `quasar::named` and `quasar::coretypes` are necessary precursors to robust Python and Lua bindings. A richer set of core types (containers, variants, temporal) enables a dynamic, type-safe object hierarchy suitable for industrial industrial infrastructure management.

## Requirements

### Structural Improvements
- [TSK-20260303-002.1] **Tree Substitution**: Implement `void NamedObject::replaceInTree(std::shared_ptr<NamedObject> replacement)` for structural substitution.
    - [TSK-20260303-002.1.1] Update parent references and re-parent all children.
    - [TSK-20260303-002.1.2] Handle root/leaf edge cases and ensure atomicity.
    - [TSK-20260303-002.1.3] Ensure thread safety following `doc/architecture/CS-0010.md`.
- [TSK-20260303-002.2] **Runtime Type Identification (RTTI)**:
    - [TSK-20260303-002.2.1] Define `virtual std::string getType() const = 0` in `NamedObject`.
    - [TSK-20260303-002.2.2] Implement overrides in all concrete subclasses.
    - [TSK-20260303-002.2.3] (BONUS/Optimization) Implement a template-based `is<T>()` and `as<T>()` helper using `std::dynamic_pointer_cast`.

### Managed Containers & Variants
- [TSK-20260303-002.3] **Named Collections**: Implement `NamedArray<T>`, `NamedMap<K, V>`, and `NamedSet<T>` in `quasar::named`.
    - [TSK-20260303-002.3.1] Elements/members must be managed as `NamedObject` children (e.g., indexed names for arrays).
    - [TSK-20260303-002.3.2] Provide standard STL-like iterators and accessors.
- [TSK-20260303-002.4] **Named Variants**: Implement `NamedVariant` and collection variants (`NamedVariantArray`, etc.).
    - [TSK-20260303-002.4.1] Support `std::variant`-like behavior for `NamedObject` types.
    - [TSK-20260303-002.4.2] Ensure type-safe retrieval and visitor pattern support.

### Advanced Core Types
- [TSK-20260303-002.5] **Temporal Types**: Implement `Date`, `Timestamp`, and `Duration` in `quasar::coretypes` and their `Named` counterparts.
    - [TSK-20260303-002.5.1] Support ISO-8601 string parsing and formatting.
    - [TSK-20260303-002.5.2] Precision must support at least microseconds (64-bit Unix epoch).
- [TSK-20260303-002.6] **Units & Quantities**: Implement a lightweight unit system (SI-based).
    - [TSK-20260303-002.6.1] Support basic conversions (e.g., Celsius to Kelvin, meters to millimeters).

### Serialization
- [TSK-20260303-002.7] **Unified Serialization**: Ensure all new types are compatible with the `quasar::named::Serialization` framework (JSON/Binary).

## Implementation Plan

1.  **Foundational RTTI & Tree Ops**:
    - Implement `getType()` and `replaceInTree()` in `NamedObject`.
    - Update existing `NamedInteger`, `NamedBoolean`, etc.
2.  **Container Types**:
    - Develop `NamedArray`, `NamedMap`, `NamedSet` templates.
    - Implement child management logic for container elements.
3.  **Variant Types**:
    - Implement `NamedVariant` using `std::variant` or a custom union-based implementation if required for performance.
4.  **Temporal & Physical Types**:
    - Implement `Timestamp` and `Duration` (likely wrapping `std::chrono`).
    - Implement the `Unit` and `Quantity` classes.
5.  **Serialization Integration**:
    - Add serialization traits/overloads for all new types in `Serialization.hpp`.
6.  **Verification & Performance**:
    - Run exhaustive unit tests and benchmarks for container overhead.

# Test and validation

1.  **Structural Integrity**:
    - Test `replaceInTree` with multi-level hierarchies and verify no broken pointers or leaked memory using **ASan**.
2.  **Type Safety**:
    - Verify `getType()` and `as<T>()` for all new types, including variants.
3.  **Container CRUD**:
    - Benchmark `NamedArray` and `NamedMap` with 10k+ elements to ensure $O(1)$ or $O(\log n)$ performance where expected.
4.  **Temporal Arithmetic**:
    - Validate `Date` and `Timestamp` against leap years, timezone offsets, and epoch overflows.
5.  **Concurrency**:
    - Use **TSan** to verify thread-safe access to shared containers and variants during tree modifications.
6.  **Cross-Platform Verification**:
    - Build and test on **Debian 12** and **Debian 13** (gcc/clang).

## Expected result

A robust, thread-safe, and highly expressive core type system that enables complex system modeling and seamless scripting integration.
