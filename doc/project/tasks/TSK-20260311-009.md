# Goal

Implement a comprehensive, **custom-built** logic and control engine (LogicEngine) within the Quasar framework. This engine shall provide runtime-definable support for State Machines, Sequential Function Charts (SFC/Grafcet), and Rule Engines. These components shall be integrated into the `NamedObject` hierarchy and leverage `ActiveEntity` for execution and reflexivity.

# Details

## Context

Industrial automation and complex system control require formal logic modeling to ensure deterministic and maintainable behavior. Unlike compile-time state machine libraries, this **custom implementation** focuses on **runtime flexibility**, allowing logic models to be defined, modified, and loaded at runtime via Lua scripts or serialization formats (JSON/SCXML). This is critical for systems where control logic may change without recompiling the core framework.

## Implementation Plan

1. **Foundations**: Define abstract interfaces for conditions and actions. Develop the ACB state machine for SFC action qualifiers.
2. **Dynamic State Machines**: Implement the custom HSM engine using a dynamic transition-table approach to support runtime construction.
3. **SFC Engine**: Develop the Active Steps loop and integrate with the Quasar `Scheduler`.
4. **C&E Matrix**: Implement the bit-parallel evaluation engine for deterministic interlock processing.
5. **Entity Mapping**: Wrap logic components into `ActiveEntity` and register reflexive fields with standardized industrial suffixes.
6. **Scripting & Tooling**: Map logic **builders** to Lua and implement SCXML/Verification exporters.

# Test and validation

- **Runtime Construction**: Verify that a complex State Machine and SFC can be defined entirely from a Lua script or JSON file without recompilation.
- **FSM Correctness**: Verify transition guards, RTC semantics, and pseudo-state transitions.
- **SFC Determinism**: Validate correct synchronization of parallel branches and timing accuracy of action qualifiers.
- **Rule/Matrix Performance**: Benchmark bit-parallel C&E evaluation latency for 1000+ interlocks.
- **Interoperability**: Verify model persistence via SCXML and discoverability through an OPC UA server mapping.
- **Formal Verification**: Use UPPAAL to verify safety properties on exported models.
- **Real-time Integrity**: Use TSan to verify thread safety within the `NamedObject` hierarchy.
