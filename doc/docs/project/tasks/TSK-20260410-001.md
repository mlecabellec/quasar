# Goal

Enhance the `resoem` project to support dynamic EtherCAT master management, including reflexive slave control (reset/reconfigure), high-fidelity diagnostic sweeping, and a dual-level observer pattern. Additionally, reorganize the project structure to establish a dedicated `tools` suite for industrial diagnostics and configuration.

# Details

## Context
As Quasar moves toward fully autonomous industrial infrastructure, the EtherCAT master (`resoem`) must evolve from a static configuration-driven driver to a dynamic, reflexive service. This task introduces the `EthercatMasterService`, which acts as a unified C++/Lua bridge for real-time bus management, allowing users to perform maintenance and diagnostic operations without restarting the primary control loops.

## Requirements

### 1. Dynamic State & Reset Management
- [ ] [TSK-20260410-001.1] **Slave Refresh**: Implement a method to trigger a status update for one or all slaves, refreshing the `NamedObject` state from the physical hardware.
- [ ] [TSK-20260410-001.2] **Forced INIT**: Implement a "Hard Reset" method allowing one or all slaves to be forced back to the **INIT** state of the EtherCAT State Machine (ESM).
- [ ] [TSK-20260410-001.3] **Reflexive Methods**: Expose these operations as `NamedMethod` nodes (e.g., `resetSlave`, `refreshStatus`) attached to the `EthercatMasterService`.

### 2. Dynamic Reconfiguration & Tree Integrity
- [ ] [TSK-20260410-001.4] **Runtime Reconfiguration**: Support changing PDO/SDO mappings and slave parameters at runtime.
- [ ] [TSK-20260410-001.5] **Tree Reflection**: Ensure that any dynamic configuration changes are instantly reflected in the `NamedObject` hierarchy.
- [ ] [TSK-20260410-001.6] **Atomic Replacement**: Utilize `NamedObject::replaceInTree` (from TSK-20260303-002) to ensure structural changes to slave topologies are thread-safe and consistent.

### 3. Diagnostic Sweeping & Visibility
- [ ] [TSK-20260410-001.7] **Decoupled Diagnostic Sweep Engine**: Implement a background sweep mechanism running in a separate management thread to ensure slave-specific issues do not impact the high-priority cyclic PDO exchange.
    - [ ] [TSK-20260410-001.7.1] Collect AL Status Codes, Hardware Error Counters, and Latency metrics.
    - [ ] [TSK-20260410-001.7.2] Implement Working Counter (WKC) failure detection per FMMU/SyncManager.
    - [ ] [TSK-20260410-001.7.3] **WKC Mini-Sweep**: Implement an automatic identification sweep to pinpoint the exact cause of WKC failures.
    - [ ] [TSK-20260410-001.7.4] **Configurable Sweep**: Provide setters/getters (e.g., `setWkcIdentificationEnabled(bool)`) to enable/disable the automatic identification sweep.
- [ ] [TSK-20260410-001.8] **Structured State Views**: Organize diagnostic data into reflexive sub-trees under each slave, including `Timestamp` fields indicating the "Last Update" for every diagnostic block.

### 4. Dual-Level Observer Pattern
- [ ] [TSK-20260410-001.9] **Slave-Level Observers**: Allow subscription to individual `EthercatSlave` objects for localized state changes (e.g., "Slave 3 transitioned to OP").
- [ ] [TSK-20260410-001.10] **Master-Level Observers**: Provide a global subscription on the `EthercatMasterService` for bus-wide events (e.g., "Topology changed", "Bus-off detected").

### 5. Service & Tooling Reorganization
- [ ] [TSK-20260410-001.11] **Unified Service API**: Refactor `EthercatMasterService` to be a first-class C++ class that is automatically bound to Lua via the `scripting` module.
- [ ] [TSK-20260410-001.12] **Specialized Tools Suite**: Create a new `tools` directory within `cmake-projects/resoem/` and implement specialized CLI tools that preserve and enhance all features of the legacy `slaveinfo` target:
    - `ecat-diag`: Comprehensive bus-wide diagnostic reporting, including:
        - AL Status Code decoding and detailed error history.
        - Mailbox protocol support verification (CoE, FoE, EoE, etc.).
        - Detailed SyncManager and FMMU memory mapping tables.
        - PDO Mapping discovery with bit-level granularity and entry names.
        - **[ENHANCEMENT]** Real-time monitoring of hardware error counters and WKC failures.
    - `ecat-ls`: Topology discovery and slave listing, including:
        - Identity verification (Vendor, Product, Revision, Serial).
        - Detailed Port status (Link, Loop, and Neighbor detection).
        - **[ENHANCEMENT]** Visualization of the physical vs. logical bus order.
    - `ecat-state`: Interactive ESM state management and reset control.
    - `ecat-sdo`: Direct SDO read/write utility and **CoE Object Dictionary browsing** (replacing `slaveinfo -od`).
- [ ] [TSK-20260410-001.13] **C++ Expert API**: Provide advanced C++ methods for low-level diagnostic handling, troubleshooting, and raw protocol interaction, optimized for debugging and performance tuning.

# Implementation Plan

1. **Service Refactoring**: Define `EthercatMasterService` inheriting from `NamedService`. Implement the management thread that handles asynchronous SDO/status requests.
2. **Method Dispatch**: Implement the C++ lambdas for `refreshStatus` and `forceInit` and attach them as `NamedMethod` objects.
3. **Observer Bridge**: Integrate the `IObserver` pattern into `EthercatSlave` and `EthercatMasterService`, ensuring thread-safe notification dispatch.
4. **Diagnostic Logic**: Expand the `resoem` core to include the sweep logic, mapping low-level SOEM/SOES status calls to the structured `NamedObject` diagnostic tree.
5. **Tree Synchronization**: Implement the logic to rebuild slave sub-trees when a dynamic reconfiguration is triggered.
6. **Tools Reorganization**: Update `CMakeLists.txt` to move targets to `resoem/tools` and update their source code to use the new service interface.

# Test and validation

- **Diagnostic Sweep Accuracy**: Run a sweep and verify that AL Status Codes match manual `ethercat` CLI tool output.
- **Dynamic Reconfiguration Stability**: Change a PDO mapping via Lua while the bus is in PRE-OP and verify the `NamedObject` tree updates without crashing the service.
- **Observer Latency**: Measure the time between a physical slave disconnection and the execution of a Lua-based observer callback.
- **Reset Reliability**: Force all slaves to INIT and verify they all transition correctly using the `SlaveRefresh` method.

## Expected result

A highly dynamic and reflexive EtherCAT master framework with an integrated diagnostic toolset, providing full visibility and control over the fieldbus from both C++ and Lua environments.
