# Goal

Implement a local cache and management system for ESI (EtherCAT Slave Information) files to automate initialization command resolution and improve offline engineering capabilities.

# Details

## Context
ESI files contain the vendor-provided definitions of EtherCAT slaves. By maintaining a local repository of these files, Quasar can automatically populate ENI `<InitCmd>` blocks and provide structured views of slave capabilities without requiring a live connection to every physical device.

## Requirements

- [ ] [TSK-20260410-003.1] **ESI Repository**: Implement a directory-based storage system for `.xml` ESI files (standardized by ETG.2000).
- [ ] [TSK-20260410-003.2] **Metadata Indexing**: Build a lightweight index (e.g., SQLite or JSON) mapping `VendorID`, `ProductCode`, and `Revision` to specific ESI file paths for fast lookup.
- [ ] [TSK-20260311-003.3] **InitCmd Resolver**: Provide a library method that, given a slave identity, extracts the recommended SDO initialization sequence from the corresponding ESI file.
- [ ] [TSK-20260311-003.4] **CLI Management**: A tool (`ecat-esi-mgr`) to add, remove, and list ESI files in the local cache.
