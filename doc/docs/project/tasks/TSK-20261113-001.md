# [TSK-20261113-001] Initialize `resoes` Clean-Room EtherCAT SubDevice (Slave) Stack

## Goal
Initialize a new `resoes` sub-project inside `cmake-projects/resoes/` as the symmetrical Quasar counterpart to `tmp/SOES/` (Simple Open EtherCAT Slave 3.0.0) and partner to `cmake-projects/resoem/`. Build a clean-room, "from scratch" C++23 EtherCAT SubDevice (slave) stack compliant with all Quasar technical standards (`CS-0010` through `CS-0080`), decoupling Quasar cleanly from GPLv2 `cmake-projects/third-party/SOES/` and enabling bidirectional virtual testing, Linux hardware HALs (`/dev/lan9252`, SPI/PRAM), and reflexive `NamedService` / `NamedObject` orchestration.

## Details

### Context
A prior repository audit established two critical facts:
1. `cmake-projects/third-party/SOES/` (vendored GPLv2 C slave stack) is not linked by `resoem` or any other Quasar module (`resoem`'s `SimulatedSlave` uses a custom in-memory C++ ESC emulator).
2. `tmp/SOES/` (SOES 3.0.0) offers a compact, field-proven architecture (ESC core + ESM, SII EEPROM emulation, Mailbox pool + CoE/FoE/EoE state machines, Object Dictionary, dynamic `0x1C12`/`0x1C13` PDO mapping, bit-sliced PDO pack/unpack, and a 4-operation ESC HAL), but relies on C global singletons (`ESCvar`, `MBX[]`), preprocessor macro configuration (`options.h`), C unions (`uint8_t`/`uint16_t` aliasing), raw pointers, and bare function pointers incompatible with Quasar's C++23 high-integrity standards (`CS-0010`..`CS-0080`).

Creating `cmake-projects/resoes/` establishes a clean, Apache/Quasar-native C++23 SubDevice stack symmetrical to `resoem`.

### Formal Standards Alignment
`resoes` implements SubDevice protocol behavior aligned with:
- **ETG.1000.3 / ETG.1000.4** (IEC 61158-3/4-12): EtherCAT Data Link Layer Services & Protocol — ESC registers (`0x0000`–`0x0FFF`), FMMU, SyncManagers (`SM0`–`SM3`), Watchdog (`0x0400`–`0x0440`), Distributed Clocks (`0x0900`–`0x09FF`), SII EEPROM interface (`0x0500`–`0x0515`).
- **ETG.1000.5 / ETG.1000.6** (IEC 61158-5/6-12): Application Layer Services & Protocol — EtherCAT State Machine (`INIT`, `PRE_OP`, `BOOT`, `SAFE_OP`, `OP`, AL Status `0x0130`, AL Status Code `0x0134`, Error/ACK), Mailbox header (6-byte), CoE (SDO Expedited, Normal/Segmented, Complete Access, SDO Information `0x08` opcodes, Emergency), FoE (`RRQ`, `WRQ`, `DATA`, `ACK`, `ERR`, `BUSY`), and EoE (`INIT_REQ`/`SET_IP`, `GET_IP`, `FRAG_DATA`).
- **ETG.1020**: EtherCAT Protocol Enhancements — Explicit Device ID, Mailbox/SDO robustness rules, dynamic PDO size calculation (`0x1C12`/`0x1C13`).

### Quasar Standards Constraints (`CS-0010`..`CS-0080`)
- **Zero `auto`**, zero `new`/`delete`/`malloc`/`free`, zero `goto`, zero `union`, zero `volatile`, zero unbounded loops (`MAX_*` constants with explicit error/throw on breach).
- Explicit boolean comparisons (`CS-0050.2`), unconditional trailing `else` on all `if-else if` chains (`CS-0060.3`).
- `[[nodiscard]]` on factories, observers, and error-returning APIs (`CS-0060.1`), `noexcept` destructors (`CS-0060.5`), `static_assert` on all binary wire structs (`CS-0020.74`).
- `std::timed_mutex` protecting all shared mutable state (`CS-0010.46`).
- Every file, class, method, field, and function documented with Doxygen `@brief`, `@param`, `@return`, `@throws` (when throwing), and `@feature` annotations (`CS-0010.45`, `CS-0030.1`), keeping every function `<= 200` lines (`CS-0010.35`) and comment cadence `<= 15` lines (`CS-0010.44`).
- Single-threaded build execution (`make -j1` per `CS-0080`).
