# Goal

Implement `ecat-top`, a high-performance Terminal User Interface (TUI) for the Quasar framework, providing a user-friendly, keyboard-driven environment for real-time EtherCAT bus monitoring, topology visualization, and reflexive control.

# Details

## Context
While CLI tools like `ecat-diag` are excellent for scripting and one-off reports, system engineers require a "live" view of the bus during commissioning and troubleshooting. `ecat-top` will serve as the "Mission Control" for EtherCAT, utilizing modern terminal capabilities to provide structured, interactive access to the `EthercatMasterService` without requiring a graphical desktop environment.

## Requirements

### 1. Interactive Layout & Navigation
- [ ] [TSK-20260410-004.1] **Multi-Pane Dashboard**: Implement a responsive TUI layout that dynamically detects terminal dimensions and supports SSH sessions:
    - **Bus Tree Pane**: A hierarchical view of the physical bus topology.
    - **Detail Pane**: Context-sensitive information for the selected slave or master.
    - **Topology Comparison Pane (ENI Mode)**: A dedicated view activated when an ENI file is provided, showing the **Expected (ENI)** vs. **Actual (Physical)** trees side-by-side.
        - **[MATCHING LOGIC]**: Use a tuple-based approach:
            - **Full Identity**: `(Vendor, Product, Revision, Bus Position)` for internal state tracking and differentiation of identical hardware.
            - **ENI Comparison**: Match Expected vs. Actual using the subset `(Vendor, Product, Revision)`.
        - **[STATUS CODES]**: Green for full match, Red for identity mismatch, Yellow for position mismatch (same type, different port), Blue for unmapped physical slave.
    - **Event Log Pane**: A scrollable, live-updating list of bus events (state changes, WKC errors).
        - **[AGGREGATION]**: Aggregate identical consecutive events into a single entry with a dynamic counter (e.g., "WKC Error [x4500]").
        - **[NOTIFICATION]**: A discrete visual indicator (e.g., a flashing icon or color change) to signal the arrival of new unread events.
    - **Master Stats Pane**: Real-time histograms or sparklines for latency and checksum health.

### 2. Data Persistence & Logging
- [ ] [TSK-20260410-004.2] **DataLogger Integration**: Utilize the `quasar::datalogger` service to persist bus activity:
    - **Event CSV**: Automatically save all bus events (unaggregated) to a dedicated CSV file.
    - **Value Change CSV**: Optionally save all interactive CoE value modifications and process data changes to a separate CSV file for audit trails.

### 3. ENI-Driven Configuration & Visibility
- [ ] [TSK-20260410-004.3] **ENI Bootstrap Loader**: Enable `ecat-top` to accept an ENI (EtherCAT Network Information) file as an optional input argument.
    - [ ] Use ENI definitions to assign human-readable names to slaves and process data values.
    - [ ] **Automatic Initialization**: If an ENI file is provided, automatically execute the specified `<InitCmd>` sequences for matching slaves during startup.
    - [ ] Support discrepancies: The tool must remain operational even if the physical bus does not match the ENI specification.
- [ ] [TSK-20260410-004.4] **On-Demand Initialization**: If no ENI file is provided, prompt the user via a modal dialog on startup to decide whether to perform a generic bus initialization.
- [ ] [TSK-20260410-004.5] **Manual Control for Unmapped Slaves**: Provide the ability to manually control and explore CoE objects for physical slaves that are not defined in the provided ENI file.

### 4. Visualization & Topology
- [ ] [TSK-20260410-004.6] **Graphical Topology Map**: Use ANSI/Unicode box-drawing characters (SSH-safe) to represent the physical port-to-port connections.
    - [ ] **Branching Support**: Correctonly render tree-like topologies including multi-port junctions (e.g., EK1122).
    - [ ] **Link Status**: Highlight "Broken Links" or "Loop Closed" states using color and line styles.
- [ ] [TSK-20260410-004.7] **Live Diagnostic Sparklines**: Implement short-term mean/min/max visualizations for master latency and slave-specific error counters.

### 5. Reflexive Control & Diagnostics
- [ ] [TSK-20260410-004.8] **Interactive Slave Orchestration**: Allow modification of slave ESM states and direct writing to CoE objects through a dedicated input modal.
- [ ] [TSK-20260410-004.9] **Bus-Wide Actions**: A dedicated menu for global operations: `Scan Bus`, `Force All to INIT`, `Sync Master Clock`, etc.
- [ ] [TSK-20260410-004.10] **WKC & Latency Analytics**: A dedicated diagnostic view showing statistical distribution of bus performance over the last 60 seconds.

### 6. Technical Architecture & Service Adaptations
- [ ] [TSK-20260410-004.11] **Master Service Enhancements**: Adapt `EthercatMasterService` to support "Partial Configuration" mode, where it can handle a mixture of ENI-configured and manually discovered slaves.
- [ ] [TSK-20260410-004.12] **Standalone Execution**: The tool shall be a dedicated executable capable of hosting its own `EthercatMasterService` instance.
- [ ] [TSK-20260410-004.13] **Dependency Management**: Integrate `ftxui` (Functional Terminal User Interface) into `cmake-projects/third-party` for modern, C++23-compliant UI components.
- [ ] [TSK-20260410-004.14] **SSH & Resizing**: Implement terminal signal handling (`SIGWINCH`) to handle dynamic window resizing and ensure rendering is optimized for standard SSH-compatible terminal emulators.

# Implementation Plan

1. **Third-Party Integration**: Add `ftxui` to `cmake-projects/third-party`.
2. **UI Framework**: Scaffold the main application loop and the multi-pane layout manager.
3. **Data Binding**: Connect the TUI components to the `NamedObject` tree of the master service.
4. **Interactive Handlers**: Implement the keyboard mapping and modal dialogs for control actions.
5. **Optimization**: Ensure the TUI refresh rate is decoupled from the EtherCAT bus cycle to prevent terminal flicker or latency.

# Test and validation

- **Input Stress Test**: Rapidly switch panes and trigger actions to ensure no deadlocks between the UI thread and the master service.
- **Terminal Compatibility**: Verify correct rendering on `xterm-256color`, `tmux`, and standard Linux VT consoles.
- **Performance Baseline**: Ensure `ecat-top` consumes less than 5% CPU on a standard industrial PC while monitoring 50+ slaves.
