# Goal

Add support for lua scripting.

# Details

## Context

Providing a lightweight, embedded Lua scripting mechanism allows managing dynamically loadable system behavior without requiring binary recompilation, significantly accelerating the iteration cycle. Integration must prioritize high precision for industrial data (64-bit integers) and real-time responsiveness.

## Requirements

- [TSK-20260303-003.1] Add support for Lua 5.4.
- [TSK-20260303-003.2] Integrate `sol2` as the primary C++ wrapper for Lua.
- [TSK-20260303-003.3] Initialize a new CMake project `cmake-projects/scripting`.
- [TSK-20260303-003.4] **Full CoreType Binding**: Expose `Variant`, `Timestamp`, `Status`, and specifically `Integer<T>` (8-64 bit, signed/unsigned) to Lua with operator parity.
- [TSK-20260303-003.5] **Named Object Bridge**: Expose `quasar::named` registry allowing `quasar.resolve("path")`.
- [TSK-20260303-003.6] **Modular Binding**: Define `ILuaModule` for extensible API registration.
- [TSK-20260303-003.7] **Component Lifecycle**: Implement `ScriptComponent` with `on_init`, `on_update(dt)`, `on_shutdown`.
- [TSK-20260303-003.8] **Robust ScriptManager**: Handle loading, **sandboxed execution**, and **thread-safe hot-reloading**.
- [TSK-20260303-003.9] **Service Discovery**: Provide a `ServiceRegistry` bridge for scripts.
- [TSK-20260303-003.10] **Real-time GC Management**: Implement time-constrained garbage collection steps.
- [TSK-20260303-003.11] **Interactive REPL**: Provide a TTY console for runtime script execution.
- [TSK-20260303-003.12] **One-Shot Execution**: Implement an `ExecuteOnce(script, args)` pattern with automatic VM cleanup.
- [TSK-20260303-003.13] **Sync/Async Execution**: Support synchronous blocking calls and asynchronous execution returning `Future`-like objects.
- [TSK-20260303-003.14] **Persistent Lua Services**: Allow implementation of services where the Lua state persists across multiple calls.
- [TSK-20260303-003.15] **Thread Pool Integration**: Execute asynchronous scripts using a dedicated thread pool to avoid blocking core loops.
- [TSK-20260303-003.16] **Advanced Object Lifecycle**: Implement a registry to track and manage the lifetime of C++ objects passed to Lua, ensuring safety beyond `sol2` defaults.
- [TSK-20260303-003.17] **Extensible C++ Classes**: Direct support for overriding C++ virtual methods and hooks within Lua scripts.


## Implementation Plan

1. **Environment & Infrastructure**:
    - Setup `cmake-projects/scripting`.
    - Create `LuaEngine` wrapping `sol::state` with custom allocators if needed for OOM tracking.

2. **Precision Type Bindings**:
    - Map `Integer<T>` to Lua userdata with arithmetic/bitwise metamethods (parity with `mastol`'s `LuaIntegers`).
    - Implement `Variant` <> Table bridge (deep copy).

3. **Lifecycle & Safety**:
    - Implement `ScriptManager` with `efsw` watcher.
    - Wrap execution in `sol::protected_function` with a global error handler.
    - Implement Sandboxing (restricted `_G`).
    - **Reference Tracking**: Implement a `LuaObjectRegistry` to manage shared/weak ownership of C++ objects.

4. **Service Bridge & Threading**:
    - Bind `ServiceRegistry` to a `quasar.service` table.
    - Integrate with `quasar::threading::ThreadPool` for async tasks.
    - Implement `LuaFuture` as the bridge for async return values.

5. **Diagnostic & Extensibility**:
    - Implement `ScriptConsole` for interactive TTY access.
    - Use `sol::base_classes` and `sol::overload` to enable easy C++ class extension.

# Test and validation

- Verify `sol2` compatibility strictly on **Debian 12** and **Debian 13**.
- **Memory Stress**: 10,000 hot-reloads without leak (ASan).
- **Precision Validation**: Verify 64-bit unsigned math in Lua matches C++.
- **Asynchronous Test**: Execute 100 concurrent async scripts and verify result aggregation through `LuaFuture`.
- **Persistence Test**: Verify that a "Counter Service" in Lua maintains its value between C++ calls.
- **Extensibility Test**: Implement a mock `Device` in Lua, overriding its `Init()` method, and verify C++ handles the Lua logic.
- **Performance**: Validate that time-constrained GC keeps frame time under 1ms overhead.
