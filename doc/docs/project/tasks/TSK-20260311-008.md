# Goal

Implement a lightweight, high-performance, and scriptable Web Server (REST + WebSocket) for the Quasar framework, enabling remote JSON-based hierarchy query (`/walk` and `/meta`), node value changes, and remote method dispatch, without any graphical user interface or frontend build toolchains.

# Details

## Context

To keep Quasar extremely lean and portable, we avoid any frontend UI framework (such as Svelte or React) and local toolchain dependencies (Node.js/npm) within the C++ CMake project. Instead, the web integration is simplified to an API-only approach. We provide a C++ `WebServerWrapper` and its Lua bindings (`scripting/plugins/net`), which expose Quasar's `NamedObject` hierarchy over standard RESTful endpoints and real-time WebSocket connections. External clients (SCADA, customized dashboards, or remote tools) can query or control the system via this unified API.

# Test and validation

- **REST API Performance**: Verify that `GET /walk` and `GET /meta` complete under 10ms for a simulated tree of 5,000 nodes.
- **WebSocket Broadcast Latency**: Ensure broadcast delta notifications are dispatched to all active sessions in under 50ms (batched every 50ms to prevent network congestion).
- **Security Protocols**: Verify SSL/TLS handshake latency, key exchanges, and connection timeouts using standard HTTPS/WSS client libraries.
