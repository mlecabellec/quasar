# Conformance Report for `scripting` project against CS-0010 (2026-03-08)

This report details the deviations from the `CS-0010.md` architecture constraint found in the files added or modified in the last 20 commits in the quasar repository. The newly added `cmake-projects/scripting` component was found to carry almost all of the deviations.

## Deviations Found

### [CS-0010.34] Use of the "auto" type is strictly forbidden
The `auto` keyword is heavily used across multiple C++ files in the scripting component, which directly violates constraint CS-0010.34.

**Files and lines with `auto` usage:**
- `cmake-projects/scripting/src/RegistryBindings.cpp`: Lines 96, 97, 112, 113, 125, 126, 138
- `cmake-projects/scripting/src/ScriptExecutor.cpp`: Lines 14, 15, 16
- `cmake-projects/scripting/src/ScriptManager.cpp`: Lines 17, 36, 45, 52, 53
- `cmake-projects/scripting/src/ScriptableNamedObject.cpp`: Line 6
- `cmake-projects/scripting/src/TypeBindings.cpp`: Lines 15, 32, 49, 61, 69, 77, 94
- `cmake-projects/scripting/test/TestExtendableClasses.cpp`: Lines 18, 44, 54
- `cmake-projects/scripting/test/TestLuaEngine.cpp`: Lines 55, 62
- `cmake-projects/scripting/test/TestLuaService.cpp`: Lines 44, 56, 66, 67, 68, 70
- `cmake-projects/scripting/test/TestScriptExecution.cpp`: Lines 24, 42, 52
- `cmake-projects/scripting/test/TestScriptManager.cpp`: Lines 28, 33, 47, 54
- `cmake-projects/scripting/test/TestTypeBindings.cpp`: Lines 22, 44, 75, 76, 77, 98, 121, 122, 127, 131

**Remediation:** Replace all instances of the `auto` keyword with their explicit type names. 

### [CS-0010.10] Use of new or delete keywords is forbidden
There is an explicit usage of the `new` keyword in the class factory method of `ScriptableNamedObject.cpp`.

**File and line:**
- `cmake-projects/scripting/src/ScriptableNamedObject.cpp`: 
  - Line 6: `std::shared_ptr<ScriptableNamedObject>(new ScriptableNamedObject(name));`

**Remediation:** Avoid using `new` explicitly. If `std::make_shared` cannot be used due to a protected/private constructor, a factory pattern or wrapper should be employed without directly exposing `new`.

## General Compliance and Verification

- The checked modified files generally comply with C++ standards, smart pointer rules, and RAII constraints where they allocate resources.
- **[CS-0010.17] Goto forbidden:** No occurrences found across the modified C++ files.
- **[CS-0010.11-12] malloc/free/calloc/realloc:** No occurrences found.
- **[CS-0010.27] sleep:** No violations related to thread sleeping without timeout were found in the scope of changes.
- **[CS-0010.45] Doxygen Documentation:** Spot-checks on newly added classes/headers (e.g. `ScriptExecutor.hpp`) confirm adherence to Doxygen commenting standards.

## Conclusion

The scripting module was broadly written correctly, but lacks conformance against a strict type deduction disallowance rule. To reach complete compliance with `CS-0010`, the project must be refactored to remove all `auto` bindings and bypass the one recorded occurrence of the explicit `new` keyword.
