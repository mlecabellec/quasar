# Feature 0080

## Title

SMP Standard - Metadata and C++ Mapping

## Description

This feature covers the metadata (Catalogue, Package, Configuration) and C++ implementation mapping from ECSS-E-ST-40-07C Rev.1 (Sections 5.4 and 6).

## Requirements

The following capabilities and features shall be provided:

- [FE-0080.1] Catalogue
    - [FE-0080.1.1] (ECSS-E-ST-40-07_1630364) Catalogue file shall conform to DRD.
    - [FE-0080.1.2] (ECSS-E-ST-40-07_1630365) Catalogues shall link to standard SMP catalogue.
    - [FE-0080.1.3] (ECSS-E-ST-40-07_1630366) No recursive Types shall be specified.
    - [FE-0080.1.4] (ECSS-E-ST-40-07_1630367) Used Types shall be visible.
    - [FE-0080.1.5] (ECSS-E-ST-40-07_1630368) XLinks in documents shall not result in recursively linked documents.
    - [FE-0080.1.6] (ECSS-E-ST-40-07_1630369) The xlink:href attribute shall be a valid URI locator.
    - [FE-0080.1.7] (ECSS-E-ST-40-07_1630370) The xlink:title attribute shall always contain the Name of the referenced named element.
    - [FE-0080.1.8] (ECSS-E-ST-40-07_1630383) A Named Element Name shall be unique in its context.
    - [FE-0080.1.9] (ECSS-E-ST-40-07_1630384) A Named Element Id shall be unique in its Document.
    - [FE-0080.1.10] (ECSS-E-ST-40-07_1630385) A Named Element Id shall not be empty.
    - [FE-0080.1.11] (ECSS-E-ST-40-07_1630386) A Named Element Name shall not be an ISO/ANSI C++ keyword.
    - [FE-0080.1.12] (ECSS-E-ST-40-07_1630387) A Named Element Name shall only contain letters, digits, and the underscore.
    - [FE-0080.1.13] (ECSS-E-ST-40-07_1630388) A Type UUID shall be unique.

- [FE-0080.2] Package
    - [FE-0080.2.1] (ECSS-E-ST-40-07_1630434) The Package file shall be in conformance with the Package file DRD.
    - [FE-0080.2.2] (ECSS-E-ST-40-07_1630435) There shall be no clashes of Type names in packages.
    - [FE-0080.2.3] (ECSS-E-ST-40-07_1630436) For each Model implementation, a different UUID shall be used.

- [FE-0080.3] Configuration Data
    - [FE-0080.3.1] (ECSS-E-ST-40-07_1630437) Files containing configuration data should be in conformance with the Configuration file DRD.
    - [FE-0080.3.2] (ECSS-E-ST-40-07_1630438) All path strings in configuration files shall be valid SMP path strings.
    - [FE-0080.3.3] (ECSS-E-ST-40-07_1630439) All field values set shall be valid values for the field type it refers to.
    - [FE-0080.3.4] (ECSS-E-ST-40-07_1630440) All path strings in configuration files shall identify either a simple field, or an array item of a simple array field.

- [FE-0080.4] C/C++ Standard
    - [FE-0080.4.1] (ECSS-E-ST-40-07_1630441) The C++ standard version relevant to SMP shall be at least C++11.
    - [FE-0080.4.2] (ECSS-E-ST-40-07_1630442) The C standard version relevant to SMP shall be at least C11.
    - [FE-0080.4.3] (ECSS-E-ST-40-07_1630443) The C/C++ standard versions used in SMP projects shall be defined and agreed on a project basis.

- [FE-0080.5] Catalogue to C++ Mapping
    - [FE-0080.5.1] (ECSS-E-ST-40-07_1630444) Table 6-1 defines C++ declaration templates.
    - [FE-0080.5.2] (ECSS-E-ST-40-07_1630445) Table 6-2 defines C++ definition templates.
    - [FE-0080.5.3] (ECSS-E-ST-40-07_1630446) All elements shall be declared within the exact same namespace as in the Catalogue.
    - [FE-0080.5.4] (ECSS-E-ST-40-07_1630447) Each type shall be declared in a dedicated header file.
    - [FE-0080.5.5] (ECSS-E-ST-40-07_1630448) Header files shall allow multiple inclusion by implementing ‘#include’ guards.
    - [FE-0080.5.6] (ECSS-E-ST-40-07_1630449) Header files shall avoid circular dependencies by using forward declaration.
    - [FE-0080.5.7] (ECSS-E-ST-40-07_1630450) Visibility kind attributes shall be mapped to ISO/ANSI C++ member access specifiers.
    - [FE-0080.5.8] (ECSS-E-ST-40-07_1630451) Table 6-3 defines C++ mapping for the Visibility kind attribute.
    - [FE-0080.5.9] (ECSS-E-ST-40-07_1630452) Simple value elements shall be mapped to C++ variables.
    - [FE-0080.5.10] (ECSS-E-ST-40-07_1630453) Array value elements shall be mapped to C++ variables.
    - [FE-0080.5.11] (ECSS-E-ST-40-07_1630454) Structure value elements shall be mapped to C++ variables.
    - [FE-0080.5.12] (ECSS-E-ST-40-07_1630455) Constant elements shall be mapped to C++ member variables.
    - [FE-0080.5.13] (ECSS-E-ST-40-07_1630458) Field elements shall be mapped to C++ member variables.
    - [FE-0080.5.14] (ECSS-E-ST-40-07_1630463) Association elements shall be mapped to C++ member variables.
    - [FE-0080.5.15] (ECSS-E-ST-40-07_1630466) Table 6-4 defines C++ mapping of Association depending on ByPointer attribute.
    - [FE-0080.5.16] (ECSS-E-ST-40-07_1630470) Parameter elements shall be mapped to ISO/ANSI C++.
    - [FE-0080.5.17] (ECSS-E-ST-40-07_1630471) Table 6-5 defines C++ mapping for the Direction kind attribute.
    - [FE-0080.5.18] (ECSS-E-ST-40-07_1630475) Property elements shall be mapped to C++ member methods.
    - [FE-0080.5.19] (ECSS-E-ST-40-07_1630480) Table 6-6 defines C++ mapping for Property depending on ByPointer attribute.
    - [FE-0080.5.20] (ECSS-E-ST-40-07_1630486) Operation elements shall be mapped to C++ member methods.
    - [FE-0080.5.21] (ECSS-E-ST-40-07_1630495) EntryPoint elements shall be mapped to C++ member pointer variables.
    - [FE-0080.5.22] (ECSS-E-ST-40-07_1630498) EventSink elements shall be mapped to C++ member pointer variables.
    - [FE-0080.5.23] (ECSS-E-ST-40-07_1630502) EventSource elements shall be mapped to C++ member pointer variables.
    - [FE-0080.5.24] (ECSS-E-ST-40-07_1630506) Container elements shall be mapped to C++ member pointer variables.
    - [FE-0080.5.25] (ECSS-E-ST-40-07_1630510) Reference elements shall be mapped to C++ member pointer variables.
    - [FE-0080.5.26] (ECSS-E-ST-40-07_1630613) Table 6-7 defines C++ mapping for the Operator attribute kinds.

- [FE-0080.6] Type Mapping
    - [FE-0080.6.1] (ECSS-E-ST-40-07_1630514) UUID variable declaration.
    - [FE-0080.6.2] (ECSS-E-ST-40-07_1630516) Type registration method.
    - [FE-0080.6.3] (ECSS-E-ST-40-07_1630518) Enumeration types shall be mapped to C++ enumerated types.
    - [FE-0080.6.4] (ECSS-E-ST-40-07_1630521) Integer types shall be mapped to C++ type definitions.
    - [FE-0080.6.5] (ECSS-E-ST-40-07_1630522) Float types shall be mapped to C++ type definitions.
    - [FE-0080.6.6] (ECSS-E-ST-40-07_1630523) String types shall be mapped to C++ structures.
    - [FE-0080.6.7] (ECSS-E-ST-40-07_1630525) Array types shall be mapped to C++ structures.
    - [FE-0080.6.8] (ECSS-E-ST-40-07_1630531) Structure types shall be mapped to C++ structures.
    - [FE-0080.6.9] (ECSS-E-ST-40-07_1630532) Class types shall be mapped to C++ classes.
    - [FE-0080.6.10] (ECSS-E-ST-40-07_1630540) Exception types shall be mapped to C++ classes.
    - [FE-0080.6.11] (ECSS-E-ST-40-07_1630551) Interface types shall be mapped to C++ abstract classes.
    - [FE-0080.6.12] (ECSS-E-ST-40-07_1630553) Model types shall be mapped to C++ classes.
    - [FE-0080.6.13] (ECSS-E-ST-40-07_1630559) Service types shall be mapped to C++ classes.

- [FE-0080.7] Package to Library Mapping
    - [FE-0080.7.1] (ECSS-E-ST-40-07_1630564) Package implemented as Static or Dynamic Library.
    - [FE-0080.7.2] (ECSS-E-ST-40-07_1630565) Library shall contain Initialise function.
    - [FE-0080.7.3] (ECSS-E-ST-40-07_1630566) Library shall contain Finalise function.
    - [FE-0080.7.4] (ECSS-E-ST-40-07_1630573) Library shall contain GetSmpVersion function.
    - [FE-0080.7.5] (ECSS-E-ST-40-07_1630575) Unix mapping as .a (Static) or .so (Shared Object).
    - [FE-0080.7.6] (ECSS-E-ST-40-07_1630588) Windows mapping as .dll.
    - [FE-0080.7.7] (ECSS-E-ST-40-07_1630594) SMP bundle composed of SMDL packages.
    - [FE-0080.7.8] (ECSS-E-ST-40-07_1630598) SMP Bundle shall include SMP manifest.
    - [FE-0080.7.9] (ECSS-E-ST-40-07_1630614) Table 6-8 defines C++ declaration templates for packages.

- [FE-0080.8] Manifest
    - [FE-0080.8.1] (ECSS-E-ST-40-07_1630605) The SMP Manifest files name shall be "SMP.MF".
    - [FE-0080.8.2] (ECSS-E-ST-40-07_1630606) The SMP Manifest file shall be an ASCII file key-value pairs.
    - [FE-0080.8.3] (ECSS-E-ST-40-07_1630607) Key and Value shall be separated by a colon.
    - [FE-0080.8.4] (ECSS-E-ST-40-07_1630608) Key shall only contain alpha-numerical characters, underscore or dash.
    - [FE-0080.8.5] (ECSS-E-ST-40-07_1630609) Value shall start at the first non-whitespace character after the colon.
    - [FE-0080.8.6] (ECSS-E-ST-40-07_1630610) The SMP Manifest file shall contain the Mandatory Keys listed in Table D-1.
    - [FE-0080.8.7] (ECSS-E-ST-40-07_1630611) The SMP Manifest file shall conform to the OSGi Core Release 6 Bundle Manifest file format.
    - [FE-0080.8.8] (ECSS-E-ST-40-07_1630612) Table D-1 defines SMP Manifest Keys.
