# Feature 0050

## Title

SMP Standard - Common Concepts and Type System

## Description

This feature covers the common concepts, type system, and basic specifications from ECSS-E-ST-40-07C Rev.1.

## Requirements

The following capabilities and features shall be provided:

- [FE-0050.1] Primitive Types specification
    - [FE-0050.1.1] (ECSS-E-ST-40-07_1630002) All SMP fields, parameters, constants and properties shall be of either a Primitive Type as per PrimitiveTypes.h in [SMP_FILES], or a User Defined Type published to the Type Library.
    - [FE-0050.1.2] (ECSS-E-ST-40-07_1630003) Mapping between SMP types, XML types and ISO/ANSI C++ types shall be as per Table 5-1.
    - [FE-0050.1.3] (ECSS-E-ST-40-07_1630004) Table 5-1 provides the detailed specification for Primitive Types (Char8, String8, Bool, Int8, UInt8, Int16, UInt16, Int32, UInt32, Int64, UInt64, Float32, Float64).
    - [FE-0050.1.4] (ECSS-E-ST-40-07_1630005) The Duration type as per Table 5-1 shall be used for specifying a duration, expressed in nanoseconds, stored in a signed 64 bit integer.
    - [FE-0050.1.5] (ECSS-E-ST-40-07_1630006) The DateTime type as per Table 5-1 shall be used for absolute time values, expressed in nanoseconds relative to 01.01.2000 12:00.
    - [FE-0050.1.6] (ECSS-E-ST-40-07_1630007) An SMP Simple Field shall be of simple type.
    - [FE-0050.1.7] (ECSS-E-ST-40-07_1630008) The AnySimple type shall hold a Primitive Type as per AnySimple.h in [SMP_FILES].
    - [FE-0050.1.8] (ECSS-E-ST-40-07_1630009) The AnySimpleArray type shall be an array of AnySimples as per AnySimpleArray.h in [SMP_FILES].

- [FE-0050.2] Time Kinds
    - [FE-0050.2.1] (ECSS-E-ST-40-07_1630010) Simulation time shall be used for keeping the progress of time with respect to the start of the simulation.
    - [FE-0050.2.2] (ECSS-E-ST-40-07_1630011) Mission time shall be used for keeping the progress of relative time with respect to a Mission Start time.
    - [FE-0050.2.3] (ECSS-E-ST-40-07_1630012) Zulu time shall be time dependent on the system clock of the host machine or an external clock source.
    - [FE-0050.2.4] (ECSS-E-ST-40-07_1630013) Epoch time shall be time dependent on the Simulation time with a fixed offset.
    - [FE-0050.2.5] (ECSS-E-ST-40-07_1630014) Epoch time may be changed with the ITimeKeeper SetEpochTime method.

- [FE-0050.3] Path string
    - [FE-0050.3.1] (ECSS-E-ST-40-07_1630015) An SMP path string shall be a representation of a valid route from an SMP object in the hierarchy to another SMP object.
    - [FE-0050.3.2] (ECSS-E-ST-40-07_1630016) Both Absolute and Relative path strings shall be supported.
    - [FE-0050.3.3] (ECSS-E-ST-40-07_1630017) The delimiter between component names in the path string shall be "/".
    - [FE-0050.3.4] (ECSS-E-ST-40-07_1630018) The delimiters between components and its children objects that are not components shall be either "/" or ".".
    - [FE-0050.3.5] (ECSS-E-ST-40-07_1630019) Trailing delimiters shall be allowed in path strings.
    - [FE-0050.3.6] (ECSS-E-ST-40-07_1630020) It shall be possible to reference the parent object by the ".." string.
    - [FE-0050.3.7] (ECSS-E-ST-40-07_1630021) It shall be possible to reference the current object by the "." string or an empty string.
    - [FE-0050.3.8] (ECSS-E-ST-40-07_1630022) The path string shall allow an element in an array to be identified by "[n]" trailing the array name.

- [FE-0050.4] Universally Unique Identifiers (UUID)
    - [FE-0050.4.1] (ECSS-E-ST-40-07_1630023) All SMP types shall have a unique UUID as per Uuid.h in [SMP_FILES].

- [FE-0050.5] Exception specification
    - [FE-0050.5.1] (ECSS-E-ST-40-07_1630024) All SMP exceptions shall inherit from the Exception class as per Exception.h in [SMP_FILES].

- [FE-0050.6] Simulation Lifecycle
    - [FE-0050.6.1] (ECSS-E-ST-40-07_1630001) Table 4-1 defines the simulation states (Building, Connecting, Initialising, Standby, Executing, Storing, Restoring, Reconnecting, Exiting, Aborting) and their descriptions.
