# [FE-0140] Standalone Script Runner and Plug-in System

## Description
This feature provides a standalone executable environment (`sre`) for the Quasar scripting engine, enabling the execution of scripts from standard input or external files without needing an embedded context. Furthermore, it introduces a dynamic plugin system that allows the scripting engine to dynamically extend its capabilities at runtime by loading shared libraries (`.so`, `.dll`).

## Purpose
- **Standalone Execution**: Facilitate quick script testing, automation, and command-line execution.
- **Dynamic Extensibility**: Allow developers to create new components (such as new `ScriptableNamedObject`s) and register them with the `LuaEngine` without recompiling the core Quasar system.
- **Component Discovery**: Provide a standard C ABI contract (`registerPluginComponents`) for shared libraries.

## Requirements Covered
- **Standalone Runner**: Ability to execute script files via CLI arguments or piped standard input (`stdin`).
- **Dynamic Loading**: Use of system calls (`dlopen`, `LoadLibrary`) to resolve and execute plugin bindings at runtime.
- **Multiple Plugins**: Support for loading multiple plugins sequentially before script execution via repeated `--plugin` arguments.

## Architecture
1. **Script Runner (`sre`)**: Command-Line Interface mapping arguments to `PluginLoader` and instances of `LuaEngine`. (Located in `cmake-projects/scripting/runner`).
2. **Plugin Loader**: C++ Wrapper for OS-level dynamic library extensions. Discovers the standardized `registerPluginComponents` entry point. (Located in `cmake-projects/scripting/src/PluginLoader.cpp`).
3. **Plugin Contract**: The standard C API signature (`QUASAR_PLUGIN_EXPORT void registerPluginComponents(sol::state_view lua)`). (Located in `cmake-projects/scripting/include/quasar/scripting/PluginContract.hpp`).
