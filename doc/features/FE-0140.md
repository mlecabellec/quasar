# [FE-0140] Standalone Script Runner, Interactive Shell, and Plug-in System

## Description
This feature provides a suite of standalone execution environments for the Quasar scripting engine, enabling both automated batch processing and real-time interactive orchestration. Furthermore, it introduces a dynamic plugin system that allows the scripting engine to dynamically extend its capabilities at runtime by loading shared libraries (`.so`, `.dll`).

## Purpose
- **Standalone Execution (`sre`)**: Facilitate quick script testing, automation, and command-line execution.
- **Interactive Mission Control (`qlsh`)**: Provide a professional-grade Terminal User Interface (TUI) for real-time system introspection, reflexive orchestration, and interactive debugging.
- **Dynamic Extensibility**: Allow developers to create new components (such as new `ScriptableNamedObject`s) and register them with the `LuaEngine` without recompiling the core Quasar system.
- **Component Discovery**: Provide a standard C ABI contract (`registerPluginComponents`) for shared libraries.

## Requirements Covered
- **Standalone Runner**: Ability to execute script files via CLI arguments or piped standard input (`stdin`).
- **Interactive Shell**: 
    - Advanced line editing and persistent history using `replxx`.
    - Real-time syntax highlighting and context-aware autocompletion (Lua globals + `NamedObject` hierarchy).
    - Multi-line statement accumulation (Alt+Enter) and safe script interruption (Ctrl+C).
    - High-fidelity tree visualization (`ls`) and metadata inspection (`help`) using `ftxui`.
    - 100% Lua 5.4 spec compliance for lexical scoping across chunks.
- **Dynamic Loading**: Use of system calls (`dlopen`, `LoadLibrary`) to resolve and execute plugin bindings at runtime.
- **Multiple Plugins**: Support for loading multiple plugins sequentially before script execution or shell startup via repeated `--plugin` arguments.

## Architecture
1. **Script Runner (`sre`)**: Command-Line Interface mapping arguments to `Environment` and executing files/stdin. (Located in `cmake-projects/scripting/runner`).
2. **Interactive Shell (`qlsh`)**: REPL interface leveraging `Environment`, `replxx`, and `ftxui` for orchestration. (Located in `cmake-projects/scripting/qlsh`).
3. **Shared Environment**: Reusable bootstrap logic for `LuaEngine` lifecycle and plugin management. (Located in `cmake-projects/scripting/src/Environment.cpp`).
4. **Plugin Loader**: C++ Wrapper for OS-level dynamic library extensions. (Located in `cmake-projects/scripting/src/PluginLoader.cpp`).
5. **Plugin Contract**: The standard C API signature (`QUASAR_PLUGIN_EXPORT void registerPluginComponents(sol::state_view lua)`). (Located in `cmake-projects/scripting/include/quasar/scripting/PluginContract.hpp`).
