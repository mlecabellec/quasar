# Feature 0260

## Title

Provide a reflexive execution and service orchestration layer.

## Description

The system shall provide a native mechanism to encapsulate and execute behavior within the `NamedObject` hierarchy, allowing discovery and dynamic triggering of system actions via `NamedMethod` and autonomous operations via `NamedService`.

The following capabilities and features shall be provided:

- [FE-0260.1] **Reflexive Methods (NamedMethod)**
    - [FE-0260.1.1] Create `NamedMethod` inheriting from `NamedObject` for executable logic.
    - [FE-0260.1.2] Support lambda-based implementation (`std::function`) with `NamedObject` parameters and return values.
    - [FE-0260.1.3] Provide access to the "Owner" (parent object) during execution.
- [FE-0260.2] **Scriptable Methods (NamedLuaMethod)**
    - [FE-0260.2.1] Create `NamedLuaMethod` inheriting from `NamedMethod` for Lua-based logic.
    - [FE-0260.2.2] Bind Lua functions with seamless conversion of parameters/return values.
- [FE-0260.3] **Service Orchestration (NamedService)**
    - [FE-0260.3.1] Create `NamedService` for autonomous, threaded operations.
    - [FE-0260.3.2] Implement dedicated management threads with lifecycle hook discovery (e.g., "configure", "run", "start", "stop" child methods).
    - [FE-0260.3.3] Support single-shot and cyclic execution models.
- [FE-0260.4] **Integration**
    - [FE-0260.4.1] Act as an "Object Bridge" for external interfaces (e.g., OPC UA, Web UI).
    - [FE-0260.4.2] Support hot-swapping of method implementations at runtime.

Project shall be located in `cmake-projects/named`.
