# Feature 0210

## Title

Provide real-time access to CAN (Controller Area Network) bus interfaces.

## Description

The system shall provide comprehensive CAN bus support, bridging the low-level Linux SocketCAN API with Quasar's high-level `ActiveEntity` and `NamedObject` hierarchy.

The following capabilities and features shall be provided:

- [FE-0210.1] **SocketCAN Support**
    - [FE-0210.1.1] Provide a C++ wrapper for Linux SocketCAN (CAN 2.0B and CAN FD).
    - [FE-0210.1.2] Support non-blocking asynchronous I/O and hardware-level ID filtering.
- [FE-0210.2] **CAN ActiveEntity**
    - [FE-0210.2.1] Implement `CanDevice` inheriting from `ActiveEntity` with lifecycle hooks (`initialize`, `start`, `stop`).
    - [FE-0210.2.2] Expose interface statistics (RX/TX counts, errors) as reflexive fields.
- [FE-0210.3] **Signal Decoding**
    - [FE-0210.3.1] Integrate with `FE-0090` (Datacodec) to map CAN frame payloads to `NamedObject` hierarchies.
    - [FE-0210.3.2] Support loading signal definitions from external configurations (e.g., JSON/DBC-like formats).
- [FE-0210.4] **Lua Integration**
    - [FE-0210.4.1] Provide Lua APIs for sending raw frames (`device:send`) and receiving frames via callbacks (`device:onReceive`).
    - [FE-0210.4.2] Organize components under the `quasar.can` Lua namespace.

Project shall be located in `cmake-projects/can`.
